  (PR #10).
- **Chat backend:** `chain` by default (`DEGA_CHAT_BACKEND=chain`). `simulated` is only forced by
  `tools/verify-tui.py` for the headless layout harness.
- **Env autogenerated on first run:** a fresh install writes `~/.canon/dega-chat.env` (0600,
  idempotent) pointing at the deployed backend and the **Sepolia v3** registry — no manual `.env`.
  The only user-provided field to open a chat node is their own private key. See
  [setup.md](setup.md) and [configuration.md](configuration.md).
- **Shipped registry default (Sepolia v3, non-TTL):** Registry
  `0xf3D30Cf5FEBCa40Ff1E6A7254BEE34f170fAb088`, MockDEGA
  `0x5f431e1a97b18C2a81c625E01B643BC836592455` (fee `50000000` base units =
  **0.00000000005 $DEGA**, rendered with the token's on-chain `decimals()`; if the RPC cannot
  answer, the UI shows base units and retries on the next refresh). One node per address +
  `usernameOfOwner` + reverse `usernameForPubkey`. This is the default in `registry_client.py`,
  in the `auth_store.py` autogen template and in `tests/test_dega_env_scaffold.py`.
- **Deployed TTL registry (Sepolia, verified on-chain 2026-09-16):** Registry
  `0x50600d8D8BA6F36F51A81d70B891e7cC81E8C8fe` on the same MockDEGA, fee `50000000`,
  `maxUsersPerNode` 10, `registrationTTL` **86400 s (24 h)**. It is what the expiry/renewal flow
  needs, and it is the address configured in `~/.canon/dega-chat.env` today. It has no entry in
  the repo's `broadcast/` records (deployed outside `DeployTestnet.s.sol`); the shipped code
  default still points at v3. See [contracts.md](contracts.md) and
  [registration-ttl.md](registration-ttl.md).
- **Rooms:** encrypted, invite-based, **off-chain** group conversations (no registry or token
  writes, no expiry model). See [rooms.md](rooms.md) and [rooms-spec.md](rooms-spec.md).
- **Presence:** opt-in public online signal, **off by default**; absence of a signal is "unknown",
  never "offline". See [chat-presence.md](chat-presence.md).
- **Earlier addresses:** `0x89fe...`/`0x0c18...` (08-31), `0x5FF8...`/`0xC577...` (09-04,
  allowed multi-node — do not use), `0x4b5f...`/`0x4f72...` (09-06). Full history in

## Elements / gating

The panel's element inventory is not user-editable. It is fetched from the DEGA API
(`GET /elements-aggregation/v2/by-email`) during login, persisted in auth state,
and used as a read-only snapshot while the panel is open.

Strategy purchase rules and durations are configured in the backend database.
Activation permanently consumes elements and grants timed access. Canon checks a
local grant before launching and synchronizes remotely after expiry; existing runs
continue. Local gating.json does not control strategy permissions.
See [timed strategy access](strategy-access.md) for activation and rollout details.

## Quick commands

```bash
# TUI with the DEGA panel (dev, always local source)
cd ~/projects/DEGA/canon-app && uv run canon .

# Headless verification after UI changes
uv run python tools/verify-tui.py --widget dega

# Read-only contract health checks (shipped default: Sepolia v3, non-TTL)
R=0xf3D30Cf5FEBCa40Ff1E6A7254BEE34f170fAb088
cast call $R "fee()(uint256)" \
  --rpc-url https://ethereum-sepolia-rpc.publicnode.com
cast call $R "maxUsersPerNode()(uint256)" \
  --rpc-url https://ethereum-sepolia-rpc.publicnode.com
cast call $R "usernameOfOwner(address)(string)" 0x0000000000000000000000000000000000000000 \
  --rpc-url https://ethereum-sepolia-rpc.publicnode.com   # must NOT revert

# TTL deploy (what ~/.canon/dega-chat.env points at today; 86400 s registrations)
T=0x50600d8D8BA6F36F51A81d70B891e7cC81E8C8fe
cast call $T "registrationTTL()(uint256)" \
  --rpc-url https://ethereum-sepolia-rpc.publicnode.com   # 86400
cast call $T "registrationOfOwner(address)(string,address,uint256,uint256,uint256,bool,uint256)" \
  0x0000000000000000000000000000000000000000 \
  --rpc-url https://ethereum-sepolia-rpc.publicnode.com
```
