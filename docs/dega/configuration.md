# DEGA / Canon — Environment variables and on-disk state

## Precedence

The panel **prefers** the file `~/.canon/dega-chat.env` (`KEY=VALUE` lines) over stale shell
environment variables. `registry_client.py` resolves in this order (for RPC, registry, PK, token):

1. Explicit argument when constructing the client.
2. `_read_chat_env_key(...)` — reads `~/.canon/dega-chat.env`.
3. `os.environ.get(...)` — process environment variable.
4. Hardcoded on-chain default (Sepolia).

`DEGA_API_URL` (the Encore backend base URL used for login/device-flow and strategy delivery)
follows the **same** precedence: explicit arg → `os.environ.get("DEGA_API_URL")` →
`read_dega_env("DEGA_API_URL")` (the generated file) → `DEFAULT_API_URL` = `http://127.0.0.1:4000`.

## Autogenerated env on first run

On a fresh install the panel writes `~/.canon/dega-chat.env` automatically (0600, idempotent —
it never overwrites an existing file). The seeded template points a new user at the deployed
backend (`DEGA_API_URL=https://ai-agents-api.degaplatform.com`) and the **Sepolia v3** registry,
with commented guidance for switching to mainnet. No manual `.env` is needed to get started;
edit the generated file only to change chain/backend/key.

## Chat variables (`~/.canon/dega-chat.env`)

| Variable | Default if absent | Description |
|----------|-------------------|-------------|
| `DEGA_API_URL` | `http://127.0.0.1:4000` (local dev) | Encore backend base URL (login + strategy delivery). This one resolves **shell env first, then the file** (`os.environ.get` → `read_dega_env`), and the generated file sets `https://ai-agents-api.degaplatform.com` |
| `DEGA_CHAT_BACKEND` | `chain` | Chat backend: `chain` (on-chain, default) or `simulated` (headless test only) |
| `DEGA_CHAT_RPC` | `https://ethereum-sepolia-rpc.publicnode.com` | Network RPC (Sepolia testnet by default) |
| `DEGA_CHAT_REGISTRY` | `0xf3D30Cf5FEBCa40Ff1E6A7254BEE34f170fAb088` | Shipped `DegaChatRegistry` default (Sepolia v3: one-node-per-address + owner lookup + reverse pubkey lookup, **no** `registrationTTL`). The **TTL** registry currently configured in this machine's `~/.canon/dega-chat.env` is `0x50600d8D8BA6F36F51A81d70B891e7cC81E8C8fe` (`registrationTTL()` = 86400) — see [contracts.md](contracts.md) |
| `DEGA_CHAT_TOKEN` | read from registry (`degaToken()`) | Fee token address ($DEGA or MockDEGA) |
| `DEGA_CHAT_PK` | — | Signer private key (testnet). Falls back to `~/.canon/wallet.env` (`WALLET_PRIVATE_KEY`) |
| `DEGA_CHAT_IDENTITY_FILE` | `~/.canon/chat-identity.json` | Nostr keypair persistence |
| `DEGA_CHAT_CONTACTS_FILE` | `~/.canon/chat-contacts.json` | Contacts |
| `DEGA_CHAT_INBOX_FILE` | `~/.canon/chat-inbox.json` | Local inbox (ciphertext) |
| `DEGA_CHAT_ROOMS_DIR` | `~/.canon/rooms/` | Directory holding the per-identity room journals |
| `DEGA_GATING_FILE` | `~/.canon/gating.json` | Feature-flag file for `gating.py` (`chat_fee_weega`, `max_users_per_node`) |
| `DEGA_STRAT_MEM_MB` | unset (no cap) | Memory ceiling the strategy runner applies to a child process |

> There is **no `DEGA_CHAT_ENV` override** for the config file path: `registry_client.py` reads
> `~/.canon/dega-chat.env` directly (the `_DEGA_CHAT_ENV` constant). Earlier revisions of this page
> advertised such a variable; it was never implemented.

> `registry_client.py`: `_DEFAULT_SEPOLIA_RPC`, `_DEFAULT_SEPOLIA_REGISTRY`,
> `_DEFAULT_SEPOLIA_TOKEN`. The default token is only a fallback; the real one is read from the
> registry.

> **Fee decimals (F3 + follow-up):** the fee display reads the token's real `decimals()` from the
> deployed registry via `ChainRegistry.token_decimals()` (cached, one RPC read). The MockDEGA on
> Sepolia reports **18 decimals**, so the live fee (`50000000` base units) renders as
> `0.00000000005 $DEGA` instead of `0.5`.
>
> If the contract cannot be read, the UI shows raw base units with “token scale unavailable”.
> Only successful precision reads are cached; the next refresh retries a failed read.
> Formatting is fixed-point (`chat_protocol.format_dega_amount` / `fee_display`).
> `tools/e2e_fee_decimals_real.py` verifies the path against the live registry.

A chain backend without `DEGA_CHAT_PK` nor a wallet fails with
`RegistryError("chain backend needs a signer key ...")` — on-chain chat needs a signer.

## Wallet (`~/.canon/wallet.env`)

- Single-line `KEY=VALUE` file: `WALLET_PRIVATE_KEY=<hex>` (with or without `0x`).
- This is the "DEGA Core burner" wallet. The Nostr keypair is **deterministically derived** from
  it (`chat_identity.py`), so `wallet <-> nostr pubkey <-> nombre.dega` are one key.
- Without a signer: falls back to a persisted keypair in `~/.canon/chat-identity.json` (0600).

## On-disk state (`~/.canon/`)

State files, all under `~/.canon/` with restrictive permissions (0600 when sensitive):

| File | Content |
|------|---------|
| `dega-chat.env` | Chat KEY=VALUE config (above) |
| `wallet.env` | Burner private key (do NOT commit this) |
| `chat-identity.json` | Persisted Nostr keypair (fallback if no signer) + the active alias |
| `chat-contacts.json` | Contacts (`wallet -> {username, pubkey_hex}`) + `my_nodes` (multi-node) |
| `chat-inbox.json` | Local inbox (ciphertext only, deduped by event id) |
| `chat-presence.json` | Opt-in presence flag per public key (presence is off by default) |
| `chat-registry.json` | Local `TestRegistry` cache (nodes/owner/expiry) used by the simulated backend |
| `auth.json` | Device authentication state (session + element snapshot from the API) |
| `elements.json` | Element snapshot persisted at login (read-only inventory for gating) |
| `gating.json` | Optional feature-flag overrides (`chat_fee_weega`, `max_users_per_node`) |
| `strategy-access.json` | Account-scoped strategy access grant cache |
| `installed.json` | Installed strategies marker |
| `strategies/` | Deployed strategies (arbiter, ivee, nba-playoff-bot, pred-market, prediction-edge, …) |
| `execution/<key>.log` | Rotated per-strategy logs |
| `rooms/<pubkey>.sqlite3` | Per-identity room journal: state, encrypted bodies, outbox, history |
| `registration-renewals/<chain>-<registry>-<wallet>.json` | Signed-but-unbroadcast renewal transaction (no private key inside) |
| `bot/` | Resident on-chain bot state |

## Strategy command selection (runner)

The runner learns how to run an installed strategy from its `package.json` (F4). Selection is
explicit — a build or checker script is never treated as the entrypoint:

| Role | Scripts accepted, in order |
|------|----------------------------|
| pre-step build | `build`, `compile` |
| dry run | `dry-run`, `start:dry-run`, `start:dry`, `scan`, `start`, `serve`, `server`, `dev` |
| live | `live`, `start:live`, `start` (falls back to the dry-run choice) |

- `StrategyManifest.run_command` is the chosen execution entrypoint; `run_hint` is what the panel
  shows before asking for confirmation.
- The build pre-step runs before the run command. If it fails while the run command needs build
  output (`dist/`, `build/`, `out/`), the run is aborted with a clear error; if the run command
  executes the sources directly (`tsx src/index.ts`), a failed build does not block it.
- A package with **no execution script** (only `typecheck`/`lint`/`test`/`check`) is reported as
  **not runnable** with an explicit hint, instead of "running" a checker.
- Examples from the real catalog: `arbiter` → `npm run scan`, `oracle-bot` → `npm run dry-run`,
  `market-forecast` → `npm run build` then `npm run start`, `ivee` → `npm run server`,
  `courtshock` → not runnable (checker-only).

## Trading: real env vars for real orders (blocked)

Only to move real capital (Polygon mainnet, Polymarket CLOB). **The project does NOT enable this
by default** — see [sandbox-live.md](sandbox-live.md).

| Variable | Use |
|----------|-----|
| `WALLET_PRIVATE_KEY` | Funded main wallet |
| `POLYMARKET_PRIVATE_KEY` | CLOB key |
| `--confirm-real` flag | Authorizes real order submission (requires funded wallet + `LIVE`) |

## Networks / endpoints

- **Default Sepolia RPC:** `https://ethereum-sepolia-rpc.publicnode.com`
- The code also carries constants for other networks (`ARBITRUM_NOVA_RPC_URL`, `MAINNET_RPC_URL`,
  `OPTIMISM_RPC`) — used depending on the contract/extension context.

## Security notes

- Do not print values of `DEGA_CHAT_PK`, `WALLET_PRIVATE_KEY`, `DEGA_CHAT_TOKEN`, etc.
- Keep `wallet.env` and `chat-identity.json` out of the repo (`.gitignore`).
- `~/.canon/dega-chat.env` is plaintext; keep it out of VCS too.

## Backend session-cookie policy (A3)

The Encore backend (see `dega_agents_fe/backend/core/logic/cookies.ts`) sets the session cookie's
`SameSite`/`Secure` from an **explicit** deployment choice, not from proxy headers (Encore's local
gateway also sets `x-forwarded-host`, so inferring cross-site from headers mislabeled local dev
cookies as `SameSite=None; Secure`).

| Env var | Effect |
|---------|--------|
| `DEGA_COOKIE_CROSS_SITE=true` | `SameSite=None; Secure` (choose only for a real cross-site topology) |
| (unset) | `SameSite=Lax`; `Secure` added on HTTPS outside a development runtime |

`authCookieClear()` mirrors the same flags so the logout cookie is actually removed.
