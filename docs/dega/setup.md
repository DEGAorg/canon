# DEGA / Canon — Project setup

Guide to prepare a development environment and run the Canon TUI with the DEGA panel.

## Requirements

- **Python 3.14** (`pyproject.toml`: `requires-python = ">=3.14"`; `.python-version` = 3.14)
- **uv** — dependency and environment manager (everything installs via `uv`)
- **foundry / forge + cast** — only to work on the contracts (build/test/deploy)
- **jq, curl** — helpers used by auxiliary scripts
- **Nostr SDK and Web3.py** — declared as package dependencies

## Development install (WSL / local)

```bash
cd ~/projects/DEGA/canon-app

# Sync the venv from uv.lock
uv sync

# The public checkout contains the Canon client and DEGA panel.
```

`pyproject.toml` declares the `canon-app` package (entry point `canon`). The
`[tool.uv.workspace]` includes `toad` and excludes `src/toad/extensions/*`.

## Install as a tool (installed snapshot)

```bash
# From the repo — installs the local code as a uv tool
bash install.sh

# Verify
canon --version
```

`install.sh` runs `uv tool install .` with `--force --reinstall`, initializes submodules (when
access is available) and checks `canon` is on PATH.

## Public installation

Use [INSTALL.md](../../INSTALL.md) for the complete agent-guided installation,
wallet preparation, generated configuration and user handoff.

```bash
git clone https://github.com/DEGAorg/canon.git
cd canon
bash install.sh
```

Build a wheel from this checkout if needed (`uv build`); no prebuilt archive is
committed to source. Update with `canon update` or pull and rerun `install.sh`.
To uninstall: `uv tool uninstall canon-app`.

## First-run onboarding (autogenerated env)

A fresh install needs **no manual `.env`**. On first launch the panel writes
`~/.canon/dega-chat.env` (0600, idempotent), pre-filled to point at the deployed backend and the
**Ethereum mainnet** registry:

```bash
# install
cd ~/projects/DEGA/canon-app
bash install.sh            # or: uv tool install dist/canon_app-*.whl --force --reinstall

# run — the env is generated for you
canon .
```

Check the generated file (only if you want to change chain/backend):

```bash
cat ~/.canon/dega-chat.env
```

It contains `DEGA_API_URL` (backend: `https://ai-agents-api.degaplatform.com` by default),
`DEGA_CHAT_BACKEND=chain`, the production `DEGA_CHAT_REGISTRY`, and an empty `DEGA_CHAT_PK`.
Existing configuration is never overwritten by an upgrade.
The signer a user must provide to open a chat node is their own **private key**
(`DEGA_CHAT_PK=` or `~/.canon/wallet.env`). One key = one address = one node.

To point at a different environment (e.g. local dev or Sepolia), edit that file and
re-run — no rebuild needed. Full reference: [configuration.md](configuration.md).

**Dev vs installed — which command runs what:**

| Command | What it runs |
|---------|--------------|
| `uv run canon .` | Always the local source (dev) |
| `canon .` | Installed snapshot (stays stale until reinstalled) |
| `bash install.sh` | Reinstalls from local source |

## Open device pairing in your browser

In the DEGA panel, click **Sign in** or press **l**. When the device code appears,
click the underlined pairing URL to open the default browser. You can also focus
the link with **Tab** and press **Enter**. Enter the displayed code on the pairing
page; Canon keeps waiting for approval while the browser is open. These controls
are handled by Canon and do not require the terminal to detect URLs automatically.

## Chat profile and controls

The Chat profile shows whether a signing wallet is configured before registration,
including its public address. Wallet configuration and registry availability are
separate: an RPC failure does not mean the wallet is missing. The chat public key
appears once in the profile; hover over the profile to see the full public values.

After registration, enter the other person's registered username beside **Invite**.
The field starts empty. **Send** sits beside the message field, and **Clear chat**
is above the conversation. Clearing the conversation keeps your registration.
In narrower panels, the profile and contacts stack above the conversation.

After registration, **Share online status** is off by default. Enabling it publishes
your activity publicly on Nostr while Chat is visible. A green dot means a recent
signed presence signal; the selected recipient also shows **Online** in text.
Silence is unknown, not proof that someone is offline, and never blocks messaging.
After hiding Chat or turning sharing off, the last signal expires within 90 seconds.
Both clients need a presence-capable Canon version. See [presence details](chat-presence.md).

Rooms are the group side of the same panel: expand **Rooms**, create one, invite
existing contacts, and accept or decline incoming invitations. Room membership is
local/off-chain (no registry write, no token fee), each message is encrypted
individually per recipient, and newly joined members do not receive prior history.
See [rooms](rooms.md) and the [rooms specification](rooms-spec.md).

A separate small **!** button marks a contact whose
chat key is unavailable. Hover over it for a short explanation, or click it / focus
it and press **Enter** for details. Messages to that contact are blocked until its
registered chat key is available. An unknown username cannot be invited.

## Relevant repo layout

```
src/toad/extensions/dega_panel/
├── pane.py                 # DEGA panel (host slot of the right-pane); mounts tabs
├── utility.py              # UtilityView — market/signal rows (live-signal parser)
├── chat.py                 # ChatView — P2P on-chain chat by default, rooms, presence
├── chat_protocol.py        # Chat protocol: openNode, invite, resolve_member
├── chat_identity.py        # Nostr keypair derived from the wallet address
├── chat_contact.py         # Contacts / active nodes
├── chat_store.py           # Local inbox persistence (ciphertext)
├── chat_presence.py        # Opt-in presence (NIP-38 / NIP-40)
├── rooms/                  # Encrypted rooms: service, protocol, journal, view, commands
├── registry_client.py      # DegaChatRegistry client (chain backend) + renewal helpers
├── auth_view.py / auth_store.py  # Device authentication + autogenerated env
├── device_client.py        # Device client (Encore backend)
├── gating.py               # Element/feature gating
├── access_grants.py        # Local strategy-access grant cache
├── strategy_access.py      # Backend eligibility + entitled archive download
├── data.py                 # Strategy catalogue
├── installer.py            # Deploys the .tar.gz (streamed, protected)
├── scanner.py              # Security scan of third-party code
├── runner.py               # StrategyRunner (dry-run / live / paper-live)
└── contracts/              # Solidity: DegaChatRegistry + MockDEGA + forge
```

## Run

```bash
# TUI with anonymous/demo access
uv run canon .

# With the DEGA panel ready
#   - create ~/.canon/dega-chat.env (see configuration.md) for explicit overrides
#   - or rely on the on-chain Sepolia defaults
uv run canon .
```

> On WSL, for headless testing use `tools/verify-tui.py --widget dega` (see testing.md).
> It does not need a real display.

## Verification after touching code

After modifying any widget or screen:

```bash
uv run python tools/verify-tui.py --verbose        # all
uv run python tools/verify-tui.py --widget dega     # DEGA panel only
uv run ruff check src/toad/extensions/dega_panel/   # lint
```

Lint/type checks do not catch layout bugs — only the headless verification does.
